# DB 경계 (A ↔ B)
상태: 초안 v2 · 2026-10-16

규칙: 테이블마다 **쓰는 쪽 하나**. 다른 쪽은 읽기만. 둘 다 써야 하면 **칸 단위로** 나눈다. 바꿀 때는 이 문서를 먼저 고치고 상대 담당에게 알린다.
담당: **A** = 총괄관리자·사업담당자 화면 · **B** = 평가위원·위원장 화면

| 테이블 | 내용 | 쓰기 | 읽기 |
|---|---|---|---|
| account | 로그인 계정. `role` = `super`(총괄) / `dept`(사업담당자). 총괄은 처음에 1개만 시드 | A | A |
| department | 기관·부서명, 대표 연락처, `status` = 사용 / 비활성 (사업이 있으면 삭제 대신 비활성) | A (총괄) | A |
| project | 사업명·담당자·소속·직급·전화, `status` = 준비 / 평가 중 / 완료 / 보관 / 폐기, `locked` (평가 중이면 수정·삭제 불가) | A | B |
| vendor | 제안사, 위원에게는 A사/B사/C사 별칭만 | A | B (별칭만) |
| document | 제안요청서·제안서 원본, 쪽 이미지, 목차, `retention` = 보관 / 폐기 예정 / 폐기됨 (칸만, 규칙 미정) | A | B |
| criterion | 평가항목·배점 (제안요청서 서식) | A | B |
| evaluator_pool | 위원 풀: 기관·부서·이름·직책·이메일·전화·분야, `department_id` (과별), 총괄은 전체 조회 | A | A |
| **project_member** | **최종 명단**: 본위원/예비, 위원장 여부, 참석, 동의 | A: 명단·위원장 / **B: 참석·동의 칸만** | A, B |
| score | 위원 × 업체 × 항목 점수, 의견(선택), 제출 시각 | B | A (결과 확정 뒤) |
| result_confirm | 위원장 확인·서명, 집계 결과 | B | A |
| audit_log | 누가·언제·무엇을 바꿨나 (총괄의 사업 수정·삭제, 부서 비활성, 자료 폐기) | A | A |

## 잠금 규칙
- `project.status = 평가 중` 이후: 총괄·사업담당자 모두 사업 정보·문서·평가항목 수정과 삭제 불가 (10-16 결정)
- 삭제는 실제로 지우지 않고 `폐기` 상태 + audit_log 기록 (보관·폐기 규칙은 정해지면 채움)
