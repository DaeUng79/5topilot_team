# DB 경계 (A ↔ B)
상태: 초안 · 2026-10-16

규칙: 테이블마다 **쓰는 쪽 하나**를 정한다. 다른 쪽은 읽기만 한다. 같은 테이블을 둘 다 써야 하면 **칸 단위로** 나눈다.

| 테이블 | 내용 | 쓰기 | 읽기 |
|---|---|---|---|
| department | 부서(과) | A | A |
| admin_account | 총괄·부서 계정 (과별 1개) | A | A |
| project | 사업명 · 담당자 · 소속 · 직급 · 전화 · 상태 | A | B |
| vendor | 제안사, 위원에게는 A사/B사/C사 별칭 | A | B (별칭만) |
| document | 제안요청서·제안서 원본, 쪽 이미지, 목차 | A | B |
| criterion | 평가항목 · 배점 (제안요청서 서식에서) | A | B |
| evaluator_pool | 부서별 위원 풀 | A | A |
| **project_member** | **최종 명단**: 본위원/예비, 위원장 여부, 참석, 동의 | A: 명단·위원장 / **B: 참석·동의 칸만** | A, B |
| score | 위원 × 업체 × 항목 점수, 의견(선택), 제출 시각 | B | A (결과 확정 뒤) |
| result_confirm | 위원장 확인·서명, 집계 결과 | B | A |

## 정할 것
- [ ] 회의의 "명단 DB 하나로 연결"을 위 표처럼 넓혀도 되는지 (위원 화면에는 사업·문서·항목·업체도 필요)
- [ ] 위원 식별: 사업별 명단 안에서 이름 + 전화번호로 찾기
- [ ] 결과를 부서관리자에게 보여 주는 시점: 위원장 확인 뒤
