# 진행 방법
기존 `docs/cookiesh1/UI_WORKFLOW.md`의 원칙(P1~P9, 시안 먼저·결정 기록)을 그대로 쓰고, 순서만 3단계로 나눈다.

| 단계 | 산출물 | 템플릿 | 끝나는 조건 |
|---|---|---|---|
| 1. 전체 구조 | ARCHITECTURE · DB_CONTRACT · v2/README(화면 지도) | — | 화면 목록과 테이블 경계에 팀 합의 |
| 2. 화면 구성 | 화면 카드 1장 + 비교 시안 링크 | [screen-card](templates/screen-card.md) | 화면마다 안 선택 → ✅ |
| 3. 세부 기능 | 버튼 단위 기능 카드 | [feature-card](templates/feature-card.md) | 입력·검증·API·DB·오류가 다 채워짐 |

## 한 화면을 정하는 순서
1. 화면 카드 초안 (오케스트레이터)
2. 레퍼런스 조사 (서브에이전트)
3. 시안 2~3개 (서브에이전트)
4. 리뷰어 점검: P1~P9 · Refactoring UI · 닐슨 10원칙 (서브에이전트)
5. 사용자가 링크를 보고 고름
6. 결정 기록 (사용자 원문)

## 규칙
- 카드는 줄글 대신 표와 목록으로, 항목당 한 줄
- 기능 이름은 `화면ID-번호` (예: `AD-07-03 랜덤 선정`)
- 테이블을 새로 쓰거나 칸을 바꾸면 DB_CONTRACT 먼저 고친다
- AI에게 맡길 때: 기존 구조는 건드리지 않고 필요한 것만 추가한다
