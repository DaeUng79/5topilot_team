# 팀 웹 화면

담당: **현수환 · cookiesh1**

메인·사업·문서·위원·평가·결과 6단계 화면, 공통 UI, mock→API 연결, 로딩·빈·오류·권한 상태를 다룹니다. 화면 방향과 결정 근거는 [UI_DIRECTION](../../docs/cookiesh1/UI_DIRECTION.md)에 있습니다.

## 스택

- React 19 + Vite + TypeScript + React Router 7, 순수 CSS(KRDS 색·글꼴 토큰)
- 글꼴: Pretendard GOV 동적 서브셋(`public/fonts/pretendard-gov`, OFL)
- API: `openapi-fetch`(생성 타입 `src/api/schema.d.ts`)와 제안 계약(`src/api/contract.ts`, 담당자 미합의 초안)
- `/api` 요청은 `127.0.0.1:8000`(apps/api)으로 프록시됩니다.

## 실행

Node 22.12 이상, 이 폴더에서 실행합니다.

```bash
npm install
npm run dev                  # 실제 API(127.0.0.1:8000) 연결
VITE_USE_MOCK=1 npm run dev  # API 없이 mock 데이터로 실행 (PowerShell: $env:VITE_USE_MOCK='1'; npm run dev)
npm run typecheck
npm test                     # Vitest: mock 응답 규칙·임시보관·CSV 파서
npm run build
```

화면 주소: http://127.0.0.1:5173

## 화면

| 단계 | 경로 | 화면이 대응하는 인수 ID (화면 표시만 / 서버 검증 필요) |
| --- | --- | --- |
| 로그인 | `/login` | 관리자는 아이디·비밀번호, 평가위원은 이름→휴대폰→인증번호 단계형. SEC-01은 서버 검증 필요 |
| 메인 | `/admin` | 처리할 일, 진행 사업 카드 |
| 사업 | `/admin/projects`, `/admin/projects/:id?tab=` | 6단계 표시, 탭: 개요·문서·평가위원·진행·결과 |
| 문서 | 탭 `documents` | 업로드·작업 상태·실패 표시(DOC-01), 근거 쪽·쪽 미확인 표시(DOC-02), AI 초안 검토·사람 확정(DOC-03) |
| 위원 | 탭 `committee`, `/admin/evaluators` | 제척 사유·인원 부족·1회 추첨·위원장 지정(COM-01·03), CSV 일괄 등록 |
| 평가 | `/eval/projects/:id/…` | 서약 바텀시트, 자료 보기·질의응답(AI-01·02), 평가하기(EVAL-01·02·04), 제출 점검·잠금(EVAL-03) |
| 결과 | 탭 `progress`·`results`, `/eval/projects/:id/chair` | 진행 현황(PROG-01), 전원 제출 전 잠금(RES-01), 위원장 확인 기록(전자서명 아님, RES-03) |

평가표 저장은 명시 저장 + 브라우저 임시보관 방식입니다. 저장 실패 시 입력을 유지하고, 새로고침하면 복원 여부를 묻습니다. 버전 충돌이 나면 서버 값과 비교하고, 저장하지 않고 이동하면 경고합니다. 임시보관은 서버 저장 성공·제출·로그아웃 시 삭제되고, 24시간이 지나면 앱 시작 때 지워집니다.

## mock 모드

- `src/api/mock.ts`가 API를 흉내 냅니다. 데이터는 localStorage에 남아 새로고침해도 유지되고, 요청마다 다시 읽으므로 두 탭 충돌도 재현됩니다.
- 합성 시드(`mockSeed.ts`): 평가 진행 중 사업 p1(본위원 5·예비 2·위원장, 2명 제출), 준비 단계 사업 p2, 후보 10명.
- **화면 상단 "MOCK · 실제 서버 아님" 띠**의 [시연 도구]에서 느린 응답, 서버 오류, 저장 실패, 빈 데이터, 데이터 초기화, 전원 제출 시드 전환을 할 수 있습니다.
- 데모 계정은 로그인 화면의 "데모 계정 (mock)"에 있습니다. 관리자는 `gansa`/`demo`, 평가위원은 예: 정모의 `010-0000-0005`.
- mock·시드·시연 도구·OTP 표시·데모 계정은 `VITE_USE_MOCK=1` 빌드에만 들어갑니다. 실제 빌드 산출물에서 해당 문자열이 없는 것을 확인했습니다.
- "mock 가정"이라고 표시한 규칙(산식, 위원장 결과 조회·확인 권한, 기준 재확정 금지, 제척 기준)은 담당자와 합의하지 않은 임시 규칙입니다.
- **mock 성공은 실제 서버 통합 성공이 아니며, 인수 기준 통과도 아닙니다.**

실제 모드에서 인증 API가 없으면 "인증 API 미연결" 안내만 보여 줍니다. 개발용 신원으로 우회하지 않습니다.
