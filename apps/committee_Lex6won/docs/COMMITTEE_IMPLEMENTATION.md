> [프로세스 검증 기록](PROCESS_REVIEW.md)과 `evidence/verification-workflow-v2.json`을 따른다.
> 초기 검사 원본과 레지스트리 반입 번들은 로컬에 보관하며 PR에는 최신 검증 자료만 포함한다.

기준일: 2026-10-13 KST. 작업 계정 Lex6won.
브랜치 `feat/committee-pool-verification`, 기준 main `17aa117`.
개인 모듈 코드와 이 문서만 변경했다. 팀 저장소 병합·운영 배포 상태와 구분한다.

## 합의한 범위

- 부서 XLSX 14개 열을 읽어 DB 등록. 파일 열기 암호는 처리 중에만 사용하고 저장하지 않는다.
- 선택 분야 전체에서 최종 총원 7/8/9명. 분야별 정원은 없다.
- 1차 예비명단은 21/24/27명. 복수 분야에 해당해도 한 번만 집계·추첨한다.
- 담당자가 통화 상태·메모를 기록하고 참여 가능한 후보 중 총원만큼 최종 확정한다.
- 최종위원을 평가과제에 배정하고 등록된 휴대전화의 문자 코드를 확인하는 흐름이다.
- 사용자 확인에 따라 지금은 문자 발송 없는 테스트 코드로 시험한다. 문자 서비스 계정은 없다.
- 화면 시안은 사용자 확인을 받았다. 원본 자료와 합성 시연 자료는 DB를 분리했다.

## 파일·인계

`apps/committee_Lex6won/committee_app`: DB·엑셀·후보·추첨·통화·확정·배정·테스트 인증.
`web`: 실제 API 연결 화면. `design`: 확인받은 합성자료 시안.
`tests`: 서비스/HTTP/API·암호화 파일·동시성·권한 경계 검증.
`contracts/openapi.json`: 요청 및 주요 응답 모델의 생성 명세. 재생성은 `export_contract.py`.
실행 방법은 [위원 모듈 README](../../apps/committee_Lex6won/README.md)에 있다.

## 부서 원본 처리

원본은 읽기 전용으로 읽어 해시가 바뀌지 않았음을 확인했다.
129행을 로컬 `data/committee.db`에 등록했다. 성명과 휴대전화가 비어 있어 모두 보완 상태다.
이 자료를 가짜 이름으로 채우거나 추첨 가능으로 처리하지 않았다.
`data/demo.db`에 별도 합성 후보 48명과 평가과제를 넣었다. 원본 DB와 섞지 않는다.
DB·원본·암호·토큰·개발 환경은 Git에서 제외했다. Git에는 원본 개인정보 행을 넣지 않았다.

## 검증 범위

- 부서 열 매핑, 복수 분야·AI 정규화, 필수정보 공란, 잘못된 파일·수식·중복 연락처.
- 암호 XLSX 정상/오류 암호 처리. 암호가 후보 데이터에 들어가지 않음.
- 미리보기 후 원자적 확정, 중간 중복 실패 시 전체 롤백, 반복·동시 확정 방지, 재실행 후 조회.
- 분야 합집합, 3배수·비복원 추첨, 부족 인원·동시 요청·재추첨 거절.
- 통화 version 충돌, 원본 스냅샷 보존, 연락처 변경 시 재연락 요구, 미저장 화면 기록 유지.
- 최종 정원·중복·예비명단 포함 여부·활성/참여 가능 조건, 확정 후 잠금, 중복 배정 방지.
- 인증 기본 차단, 미배정 후보 거절, 코드 만료·오입력 제한·재사용·다른 과제 접근 거절.
- Host·Origin·클라이언트 헤더, 인증 데이터 입력값의 오류 응답 노출 제한, 스트리밍 크기 제한.
- 업무/시연 앱을 동시에 쓸 때 포트별 관리자 쿠키 분리.

최종 실행 결과는 `apps/committee_Lex6won/evidence/verification.json`을 따른다.
로컬 HTTP 응답과 자료 조회를 검사했지만 자동화 브라우저 연결이 없어 클릭·시각 QA는 미실행이다.
FastAPI TestClient에서 httpx 사용의 deprecation 경고 1개가 있으며 런타임 실패가 아니다.

## 보안·게이트

패키지 게이트로 직접·전이 패키지와 개발 도구의 고정 버전을 검사했다.
취약한 python-multipart 구버전과 대기 기간 미충족 전이 버전은 설치하지 않고 대체했다.
venv 기본 pip/setuptools의 취약 버전도 검사한 수정 버전으로 교체했다.
`gvskb scan --check-deps --include-installed` 결과를 `evidence/security-current`에 남긴다.
테스트의 `httpx.Response.json()`을 None 역참조로 보는 패턴 경고와 합성 전화번호 경고는
실제 결함·개인정보 노출과 구분하여 검토한다. 경고를 숨기거나 판정을 승인으로 바꾸지 않는다.

`gg verify`는 이 저장소 하네스 미초기화로 실패한다. 초기화 시도도 설치된 실행기의
`shared/harness-core.yaml` 누락으로 실패했다. 이 검증은 **판정 불가**이며 완료/승인으로 표현하지 않는다.
관련 Git 훅·CI를 변경하거나 우회하지 않았다. 이 문제가 해결되기 전 게이트 통과/병합 준비 완료가 아니다.
