# 평가위원 등록부터 로그인까지 점검

2026-10-13 KST · Lex6won 담당 모듈 · 로컬 테스트 버전

## 확인된 차이와 수정

| 사용자 순서 | 이전 구현의 차이 | 수정한 동작 |
| --- | --- | --- |
| 1. 엑셀 또는 한 명씩 풀 등록 | 두 기능은 있었으나 다항목 모달·안내가 복잡 | 등록을 별도 페이지로 분리, 핵심 5개 항목 우선 표시, 나머지는 추가 정보로 접음 |
| 2. 제안서 등록 시 프로젝트 자동 생성 후 3배수 추첨 | 프로젝트를 직접 생성, 제안서 업로드 없음 | PDF 업로드를 DB에 저장하면서 프로젝트 생성, 다음 페이지에서 7/8/9명·분야 선택 후 21/24/27명 추첨 |
| 3. 최종 7~9명 + 예비 3명 선택 | 예비위원 3명의 독립 저장·검증 없음 | 최종·예비 버튼, 중복·정원·참석 여부·활성 상태 검증, 최종/예비 합계 표시, 확정과 배정 원자적 저장 |
| 4. 평가일 테스트 로그인 | 이름·전화 입력 후 개발 코드 추가 입력, 관리자 메뉴 노출 | 관리자 메뉴 없는 위원 전용 페이지, 이름 + 등록 전화/이메일, 로그아웃·이전 세션 폐기, 최종위원만 접속 |

3배수 추첨 명단과 최종 예비위원 3명은 별개의 자료다. 최종위원과 예비위원은 겹칠 수 없다.
최종위원만 평가과제 배정을 받는다. 예비위원의 승격·위원 교체 절차는 이번 범위에 포함하지 않았다.
평가일을 강제로 제한하지 않아 사전 테스트가 가능하며, 운영 평가 기간 제어는 후속 연결 범위다.

## 화면 구성

- `#pool`: 후보 조회. `#candidate`: 한 명 등록/수정. `#import`: 엑셀 미리보기·저장.
- `#projects`: 프로젝트 선택. `#proposal`: 제안서 등록. `#draw`: 분야·인원 확인과 추첨.
- `#final`: 일정 확인을 저장하고 최종/예비 역할 선택. 통화 메모는 접힌 항목에서 선택 입력.
- `#assignment`: 확정 명단과 위원 접속 주소. 별도 배정 버튼 없이 확정 시 자동 배정.
- `#auth?project=...`: 프로젝트명·이름·연락처만 표시하는 위원 로그인. 성공 시 평가 대기와 로그아웃.

44px 이상 버튼, 명시적 라벨, 키보드 포커스 표시, 좁은 화면의 단일 열과 모바일 메뉴를 코드에 적용했다.
이 항목들은 코드 확인 결과이며 실제 화면 배치·터치·키보드 조작의 통과를 의미하지 않는다.

## 실행 검증

- 35개 Python 테스트 통과, committee_app 커버리지 94%. Ruff·mypy·JavaScript 문법 검사 통과.
- 7/8/9명 각각 제안서 업로드 → 자동 프로젝트 → 분야 합집합 → 3배수 → 최종/예비 → 로그인 검증.
- 중복 PDF 등록으로 프로젝트가 늘지 않음. 잘못된 파일·부족 인원·추첨 후 조건 변경 차단.
- 예비위원 2명/중복/최종위원 겹침, 미배정 로그인, 다른 과제 세션 사용 차단.
- 이름·휴대전화와 이름·이메일 로그인, 이메일 중복·형식, 분당 요청 제한 검증.
- 공용 기기에서 새 로그인으로 세션 교체, 실패/422 입력 오류/로그아웃 시 이전 세션 무효화 검증.
- DB revision 1 → 2 및 재시작 검증. 실행 중 업무 후보 129명·시연 후보 48명의 저장 payload가
  업그레이드 전 백업과 동일함을 비교했다. 백업·원본·DB는 Git 제외 경로에만 있다.
- 내부망 테스트 Host와 비로컬 클라이언트의 관리자 세션 차단을 TestClient로 검증.
- 실제 5187/5188 서버의 화면 파일·API 응답 확인. 양쪽 모두 테스트 로그인 옵션으로 실행 중.

## 미완료 검증과 제한

Chrome 클릭·시각 검증을 시도했으나 Computer Use가 현재 브라우저 URL을 신뢰성 있게 확인하지
못해 정책 검사를 수행할 수 없다는 오류로 중단했다. 도구 중단 후 UI 입력을 더 수행하지 않았다.
**실제 브라우저 흐름·반응형 화면·태블릿 실기기 테스트는 통과로 보고하지 않는다.**

제안서 파일은 현재 PDF 8MB 이하만 받는다. HWP/HWPX/DOCX, 여러 업체 제안서를 한 사업에 묶기,
팀 기존 제안서 등록 이벤트 연결은 공통 사업 모델과 연계할 후속 범위다.
실제 문자·본인인증, 운영 관리자 인증, 평가 문서/채점 화면은 미연결이다.
내부망 실행 옵션은 추가했지만 현재 서버는 localhost로만 실행 중이다.

`gg verify`는 하네스 미초기화로 종료 코드 1, **판정 불가**다. 훅/CI를 우회하지 않는다.
사용자 요청에 따라 개인 포크의 작업 브랜치와 팀 저장소 Draft PR로 검토를 요청한다.
이는 통합·운영 검증이나 병합 준비 완료 판정이 아니다. 실제 업로드·PR 상태는 GitHub 기록을 따른다.

## 보안 검사 검토

`evidence/security-workflow-v2`: 의존성 취약·미검사·조회 실패·차단은 0건이며 전체 판정은 conditional.
소스 패턴 경고는 숨기거나 승인으로 덮어쓰지 않았다.

- HTML 삽입 경고: 고정 템플릿에 사용자 문자열은 `esc()`로 이스케이프한다. 이름·소속·분야·메모·이메일·프로젝트명·오류 문자열을 확인했다.
  ID는 서버 생성 UUID, 인원/행 번호는 정수, 전화 표시는 서버 검증 숫자로 제한한다. 실행 코드 삽입을 허용하는 입력 경로는 확인되지 않았다.
  CSP도 외부/인라인 스크립트·frame embedding을 제한한다. 실제 브라우저 XSS 동작 검증은 미실행이다.
- Python None 경고: 테스트의 HTTPX Response `.json()` 체인을 dict `.get()`으로 보는 패턴이다.
- 전화번호·내부 IP: 합성 fixture와 내부망 접근 경계 테스트용 상수이며 원본 연락처나 실제 부서 네트워크 정보가 아니다.

팀 인계 API: `apps/committee_Lex6won/contracts/openapi.json`. 공유 소스·팀 평가 모듈·공통 DB는 수정하지 않았다.
