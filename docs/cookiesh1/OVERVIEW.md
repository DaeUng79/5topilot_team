# 심사임당 웹 작업 한눈에 보기 (cookiesh1)

기준 시각: 2026-10-12 · 브랜치 `feat/web-interview-track` · 구현 위치 `apps/web_cookiesh1/`

> **mock 확인 ≠ 인수 통과.** 아래 "완료"는 가짜 서버(mock)에서 화면이 동작했다는 뜻입니다. 팀 인수 기준([ACCEPTANCE](../testing/ACCEPTANCE.md))을 통과했다는 뜻이 아닙니다.

## 1. 한 줄 요약

간사(관리자)와 평가위원이 쓰는 웹 화면을 인터뷰로 방향을 정하고, 가짜 서버(mock)로 먼저 만들어 동작을 확인했습니다. 실제 서버 연결은 아직입니다.

| 배지 | 상태 |
|---|---|
| mock 동작 | 동작함 (관리자 7단계 포함) |
| 실제 API | **미연결** (PR #1 서버를 로컬에서 띄워 보지 않음) |
| 인수 시나리오 | **미실행** |
| 제안 계약 | 전부 "제안" (담당자 합의 전) |

## 2. 업무 워크플로우

팀 공동 흐름 7단계마다 어느 화면에서 하는지, 누가 서버를 맡는지, 어떤 인수 ID로 확인하는지 정리했습니다.

```mermaid
flowchart TD
    S1["1 제안요청서 등록<br/>DOC-01 · DaeUng79"] --> S2["2 평가기준 확정<br/>DOC-03 · DaeUng79, u-jing"]
    S2 --> S3["3 제안서 등록 + 제안사<br/>DOC-01, DOC-06 · DaeUng79"]
    S3 --> S4["4 평가위원 선정<br/>COM-01, COM-03 · Lex6won"]
    S4 --> S5["5 평가 진행<br/>EVAL-01~04, PROG-01 · u-jing"]
    S5 --> S6["6 결과 취합 · 위원장 확인<br/>RES-01~03 · u-jing"]
    S6 --> S7["7 보고 · 완료<br/>RES-03, CLOSE-01 · u-jing"]

    A1(["간사 화면<br/>/admin/projects/:id/rfp"]) -.-> S1
    A2(["간사 화면 criteria"]) -.-> S2
    A3(["간사 화면 proposals"]) -.-> S3
    A4(["간사 화면 committee"]) -.-> S4
    A5(["간사 화면 progress<br/>일정 · 참석 · 제출 현황"]) -.-> S5
    A6(["간사 화면 results"]) -.-> S6
    A7(["간사 화면 close"]) -.-> S7

    S4 ==> E1(["평가위원 로그인<br/>이름 → 휴대폰 → 인증번호"])
    E1 --> E2(["청렴서약"])
    E2 --> E3(["자료 보기 · 평가하기 · 제출<br/>/eval/projects/:id/..."])
    E3 ==> S5
    S6 ==> C1(["위원장 확인<br/>/eval/projects/:id/chair"])
    C1 ==> S7
```

세 역할이 만나는 곳은 굵은 선입니다.

| 만나는 곳 | 내용 |
|---|---|
| 4 → 평가위원 로그인 | 간사가 위원을 뽑으면 위원이 로그인하고 서약합니다 |
| 평가 제출 → 5 | 위원이 낸 점수가 간사 진행 현황에 모입니다 |
| 6 → 위원장 확인 → 7 | 전원 제출 후 위원장이 확인해야 간사가 사업을 완료합니다 |
