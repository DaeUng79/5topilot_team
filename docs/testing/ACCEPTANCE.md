# 심사임당 인수검증표

작성 기준: 2026-10-10 KST. 아래 항목은 [공동 개발 실행계획](../team/DEVELOPMENT_PLAN.md)의 **검증 계획**입니다. 기존 문서 처리 테스트 94개 통과와 별개로 아래의 새 통합·인수 시나리오는 모두 **미실행**입니다. 데모 화면 표시, HTML의 설명, 테스트 파일 존재만으로 통과 처리하지 않습니다.

## 1. 실행 조건과 증거

- 개발자별 로컬 DB와 합성 데이터로 시작하고, 공동 검증은 별도 테스트 환경에서 수행합니다.
- 실행 기록에는 커밋 SHA, 환경, DB migration revision, fixture 버전, 실행자, 검토자, 명령/재현 절차, 예상·실제 결과, 증거 링크를 남깁니다.
- 상태는 `미실행 / 통과 / 실패 / 차단 / 범위 외`로 구별합니다. 차단은 원인·선행 이슈를, 범위 외는 합의한 이유를 적습니다.
- 작성자가 자동검증을 수행하고 표에 지정한 동료가 결과를 재현합니다. Lex6won이 PM으로 인수조건·진척을 조율하고 DaeUng79가 저장소 병합·통합을 조율합니다. 본인 구현은 본인만의 검토로 통과시키지 않습니다.
- 정책이 미정인 계산·추첨·제출 변경은 정책 확정 전 통과시킬 수 없습니다. 실제 운영 규칙 대신 테스트용 정책을 쓰면 그 범위를 표시합니다.

## 4. 자동검증과 동료검증의 경계

| 시점 | 필요한 검증 | 주의사항 |
| --- | --- | --- |
| 문서 처리 PR | 변경된 파서·추출·기준·UI 관련 회귀검증, 원문 대조 | LLM 호출은 기본 CI에서 mock/저장된 응답 사용. 실제 호출 결과와 비용은 별도 기록 |
| API·DB PR | 도메인 규칙, 권한, 계약, PostgreSQL 트랜잭션·경합, migration | SQLite 성공만으로 PostgreSQL의 잠금·동시성 통과를 대체하지 않음 |
| 화면 PR | 타입/빌드, mock 계약, 실제 API 연결, 로딩·오류·빈 상태 | mock과 정적 데모 성공은 실제 서버 통합 성공과 별도로 기록 |
| 통합 PR·마일스톤 | DOC → COM → EVAL → RES 전체 흐름, 작성자 외 재현 | 미완성 선행 기능은 차단 사유로 기록. 우회해 통과 처리하지 않음 |
| 운영 준비 | 실제 인증, 파일 접근, worker 실패 복구, 백업 복원·온프레미스 전환 | 개발용 임시 인증·seed·공유 관리자 계정으로 운영 검증 완료 표시하지 않음 |

이번 작업에서 기존 문서 처리 테스트 94개가 통과했습니다. 이는 문서 처리 단위·회귀검증 결과이며 위 표의 웹/API/DB 통합, 에이전트 인수검증, 브라우저 E2E·운영 검증 통과를 뜻하지 않습니다. HTML 및 PR #1의 웹/API용 CI 설명도 실제 이번 실행과 구별합니다. CI 명령·체크 이름은 채택된 코드와 워크플로에서 확인한 뒤 PR 기록에 적습니다.

MongoDB/GridFS 문서 저장 검증은 DaeUng79가 주관합니다. 업무 데이터·migration 검증은 u-jing이 주관하고 DaeUng79가 함께 검토하며 위원 데이터 영향은 Lex6won도 확인합니다. cookiesh1은 모든 연결 화면의 오류·빈 상태·근거 열람을 검증합니다.
