## 4. 다음 세 번의 PR 범위

1. **실행 복구 PR:** 개발 폴더 유지, import와 실행·설정 경로 정합화, 테스트 수집 복구, 실제 실행 명령 갱신. 동료는 새 체크아웃에서 재현한다.
2. **정확성 PR:** 환경 경로를 제외한 revision 규칙, 원문 조회 정규화, 조기 종료의 명시적 모드·검사 범위, 행별 근거·검토 상태의 계약과 재현 테스트. 기존 결과 ID와의 호환 전략을 포함한다.
3. **저장·검색 기반 PR:** 저장소 경계, 합성 DB 비교, 사업 권한이 적용된 청크·검색 계약. 이후 문서 API와 RAG UI를 기능 단위로 연결한다.

첫 PR에서 DB 이관까지 한꺼번에 진행하지 않는다. 현행 MongoDB의 데이터는 별도 전환 계획과 검증 결과에 따라 옮긴다.

## 5. 합의할 API 계약 초안

경로·필드는 논의용이며 현재 구현되어 있지 않다. 인증 사용자의 권한을 서버에서 검사하고 클라이언트가 보낸 `project_id`만 신뢰하지 않는다.

| 제안 API | 입력 | 응답·규칙 |
| --- | --- | --- |
| `POST /projects/{project_id}/documents` | HWPX, 문서 종류, 업체 연결, 중복 방지 키 | `project_document_id`, `content_id`, `job_id`, 처리 상태; 로컬 파일 경로를 입력으로 받지 않음 |
| `GET /projects/{project_id}/document-jobs/{job_id}` | 권한 있는 작업 ID | 파싱·페이지·색인 각각의 상태, 오류 코드, 재시도 가능 여부, 대상 revision |
| `GET /projects/{project_id}/documents/{id}/revisions/{revision}/blocks/{block_id}` | 문서·버전·블록, 선택 셀 | 원문·근거 위치·페이지 매핑 수준; 타 사업/삭제/허용되지 않은 버전 거절 |
| `POST /projects/{project_id}/search` | 질문, 문서 종류/업체 등 허용된 필터 | 근거 목록·검색 방식·활성 버전·색인 상태, 점수를 신뢰도 확률로 표현하지 않음 |
| `POST /projects/{project_id}/chat` | 질문, 접근권한이 재검증되는 대화 ID | 답변·인용·검토 필요·근거 없음 사유·검색 실행 ID |

문서 처리 상태는 `queued → parsing → parsed`와 실패 상태로 관리하고, 페이지 매핑/미리보기/임베딩은 별도 상태를 둔다. `parsed`를 `approved`로 취급하지 않는다. 사람의 기준 승인·버전 고정은 u-jing의 평가 모듈과 별도 계약으로 연결한다.

중복 요청은 동일 키·동일 입력에 같은 작업을 반환하고, 같은 키에 다른 입력이면 충돌로 처리한다. 작업자는 재시도 가능하게 만들고, 이전 작업이 늦게 완료되어 새 활성 버전을 덮어쓰지 않도록 조건부 갱신을 사용한다.
